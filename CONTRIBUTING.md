# Contributing to Piepowder

Piepowder is a public experimental project with reserved rights. We welcome original
proposals, reproducible problem reports, documentation feedback and discussion of
useful research directions. Start with the current [roadmap](docs/roadmap.md) and
an observed issue.

## Agree a contribution before implementation

Read [RIGHTS.md](RIGHTS.md). Open an issue to discuss the proposed scope and obtain
the maintainer's applicable permission before implementing or submitting code or
documentation. Identify the authorship and provenance of contributed material.
Public visibility leaves the existing rights position in force.

Keep the scope small, preserve existing behaviour and explain the result in a
pull request. Run the documented tests and demonstration before proposing a
substantive change.

Use fictional examples with pre-specified expected results. Test unknown and
adversarial outcomes as carefully as successful checks. Never add client data,
credentials or model-generated legal findings disguised as human review.

Explain any change to a schema, digest envelope or acceptance rule and version it
explicitly. Preserve old fixtures or document their migration. Do not introduce
network, payment, licence or data-disclosure capabilities as incidental refactoring.

## Credit and collaboration

Accepted contributions will be credited in the relevant pull request or release
notes using the contributor's preferred name or GitHub handle. Describe which
work you performed and any tools or sources that materially assisted it. Record
independent review only when it actually occurred.

Where funded work becomes available, collaborators can discuss paid engineering,
research, documentation or support assignments. Agree roles, deliverables,
intellectual-property arrangements and payment terms in writing before work begins.
Earnings or revenue sharing depend on the specific agreement and actual funding.
